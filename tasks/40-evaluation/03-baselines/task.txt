TASK: Baselines — identity, model v1, and a prompted instruct model

GOAL
  A number means nothing without something to beat (audit E3). Three baselines on the
  same sets and the same metrics. The third one decides whether fine-tuning is worth
  having at all (GOAL.md stop condition).

CONTEXT
  tasks/GOAL.md (stop condition)
  scripts/synthesize.py:31-54 (how the owner's llama-server is called — same request shape)
  scripts/generate_eval_outputs.py
  tasks/40-evaluation/02-shipped-path-eval/ (report format)

SCOPE
  + identity: model_output = input. Generated by a flag of generate_eval_outputs.py; no model.
  + v1: the v1 MLX model on MAC through the same script.
  + prompted_instruct: on HOST, the owner's llama-server (127.0.0.1:8080) with a fixed system prompt asking for a terse pre-2021 kernel/PostgreSQL-style commit or PR text that keeps every identifier, number and reference, output only. temperature 0.2. The prompt text is stored in this task directory (prompt.txt) before any output is looked at, and is not tuned afterwards.
  + Sets: eval_heldout and real_ai for all three; owner for identity and v1 only (owner files do not leave the Mac).
  + Scoring with the same evaluate.py; reports baseline_<name>_<set>.json in this task directory; one comparison table in NOTES.md.
  − Tuning the instruct prompt until it loses: forbidden; one prompt, written first.
  − Paid APIs as a baseline: not used (no key, no budget decision).

OUTCOME
  Eight baseline report files in tasks/40-evaluation/03-baselines/ and the table in NOTES.md.

VERIFY (EVAL)
  1. baseline_identity_real_ai.json: copy_rate == 1.0 and fact_retention_mean == 1.0
     (reverse control for both metrics: identity is the known worst and known best case).
  2. prompt.txt has a git commit date earlier than the prompted_instruct output files.
  3. Every report names the set's sha256 from the manifests, so all rows compare the same inputs.
  4. `ruff check . && mypy . && pytest && python3 scripts/coverage_gate.py --run` exits 0.

ROLE
  EVAL

DEPENDS
