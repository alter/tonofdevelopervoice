TASK: scripts/convert_mlx.py — MLX 4-bit model directory with a manifest

GOAL
  Turn the merged bf16 model (~16 GB) into the artefact the Mac actually runs: MLX 4-bit,
  ~4.6 GB, which fits into the <8 GB the MacBook usually has free (audit S1, D1).
  Runs on MAC.

CONTEXT
  tasks/10-serving/01-merged-export/EXPORT.json (the Hub repo to convert)
  tasks/DECISIONS.md (D1 — pinned versions mlx-lm==0.31.3, mlx==0.32.2)
  pyproject.toml (dependency groups)
  .gitignore (models/ is ignored)
  docs/runbook-deploy.md

SCOPE
  + pyproject.toml: new dependency group `mlx` = ["mlx-lm==0.31.3; sys_platform == 'darwin'"]; `uv sync --group mlx` installs it. `uv.lock` regenerated by uv, not by hand.
  + scripts/convert_mlx.py with arguments: --hf-path (Hub repo id or local dir), --mlx-path (default models/<name>-mlx-q4), --manifest PATH, and a second mode --verify MODEL_DIR MANIFEST.
  + Conversion is one call: mlx_lm.convert(hf_path=..., mlx_path=..., quantize=True, q_bits=4, q_group_size=64). This signature was checked against the installed 0.31.3 on 2026-09-19.
  + Manifest: source Hub repo + commit, q_bits, q_group_size, mlx and mlx-lm versions, sha256 and size of every file in the output directory, total size.
  + --verify recomputes every sha256 and exits non-zero on the first mismatch or missing file.
  + Smoke run, recorded in NOTES.md: `mlx_lm.generate --model <dir> --prompt "<one formatted prompt>" --max-tokens 64` — copy the printed tokens-per-sec and peak memory lines.
  + Upload the MLX directory to the Hub as `<hf-user>/tonofdevelopervoice-qwen3-8b-v1-mlx-q4` with `hf upload`; record repo + commit in the manifest.
  + Save the manifest as tasks/10-serving/02-mlx-conversion/MLX_MANIFEST.json.
  + If conversion on the Mac dies from memory pressure: stop, write the evidence to NOTES.md, and try the same script on HOST inside the training venv with `pip install "mlx[cpu]==0.32.2" mlx-lm==0.31.3` (UNVERIFIED that the Linux CPU wheel exists for this version — check `pip download` first; if it does not, BLOCKED.md).
  − Deleting anything from ~/.cache/huggingface (the 16 GB fp16 base is the owner's cache): not touched; mention its size in NOTES.md so the owner can remove it.
  − Python code that loads the model for rewriting: owned by 10-serving/04-mlx-backend.
  − Other quantisation levels (3-bit, 8-bit, mixed): not now; one artefact.

OUTCOME

  4 and 6 GB, and tasks/10-serving/02-mlx-conversion/MLX_MANIFEST.json in git.
