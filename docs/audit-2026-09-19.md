# Audit 2026-09-19 — why the trained model is unusable on the Mac, and what to rebuild

Read-only review of the repository at commit `29827b3`, of the owner's overnight run on the
MacBook (M2, 24 GB) and of the v1 plan log. No code was changed. Every finding carries its
evidence. The work that follows from it lives in `tasks/`; decisions are in
`tasks/DECISIONS.md`.

## 0. The two facts that matter

| # | Fact | Evidence |
|---|---|---|
| A | One file takes ~3.4 hours, i.e. ~48 seconds per generated token. | `/tmp/pr/1.rewritten.txt` written 05:45, `/tmp/pr/2.rewritten.txt` written 09:10 (`ls -la /tmp/pr`); each output is ~256 tokens. |
| B | The model does not rewrite. Both outputs are a verbatim copy of the beginning of the input, cut off mid-sentence. | Common prefix of input and output = 1039 of 1039 output chars (file 1) and 1200 of 1200 (file 2). Copies kept in `data/eval_real/owner/` and `data/eval_real/owner_v1_outputs/`. |

Fact A is a serving defect. Fact B is a data + training + evaluation defect. Fixing A alone
gives a fast model that copies its input.

## 1. Serving (why it is slow)

**S1. Root cause of the speed: 16 GB of fp16 weights on a machine with <8 GB free.**
`src/tonofdevelopervoice/serve/peft_backend.py:38` loads `Qwen/Qwen3-8B-Base` with
`dtype=torch.float16` (8.2B params x 2 bytes = ~16 GB; the HF cache directory
`models--Qwen--Qwen3-8B-Base` is 16 GB on disk) and line 40 moves it to MPS. The host has
24 GB total and `sysctl vm.swapusage` showed 7132 MB of 8192 MB swap in use. Every token
pages weights in from swap. No amount of code tuning fixes this; the artefact must be
~4-5 GB (4-bit).

**S2. Hard cap of 256 new tokens.** `peft_backend.py:26` and `unsloth_backend.py:8`. Any
input whose rewrite needs more than 256 tokens is silently cut mid-sentence (both owner
outputs end mid-sentence). Nothing reports that the cap was hit.

**S3. No input-length handling.** The model was trained with `max_seq_length: 1024`
(`training/config.yaml:6`). The owner's PR descriptions are 1.7-4.2 KB (~450-1100 tokens)
plus the prompt, i.e. at or beyond the trained length. No guard, no warning.

**S4. What is served is not what was trained or evaluated.** Training and the v1
evaluation ran Unsloth on a bitsandbytes 4-bit base on CUDA; the Mac runs an unmerged LoRA
on an fp16 base through a second, duplicated backend (`peft_backend.py` vs
`unsloth_backend.py`). Evaluation numbers say nothing about the Mac path.

**S5. Greedy decoding, no repetition control, generation settings implicit.** `generate()`
is called with only `max_new_tokens`. Greedy decoding on a weakly tuned base model is the
configuration most prone to copying and loops.

**S6. Fragile output slicing.** `generated[len(prompt):]` (`peft_backend.py:54`) assumes
decode(encode(prompt)) == prompt character for character.

**S7. `scripts/batch_rewrite.py` has no resume, no timing, no failure signal.** A re-run
redoes finished files; there is no tokens/second, and a truncated output exits 0.

**S8. Model is loaded per process.** Every CLI call pays the full load. Acceptable for a
4-5 GB mmap-ed MLX model (seconds), not for 16 GB.

## 2. Data (why it copies — part 1)

**D1. The corpus is one year deep.** `github_api.py` pages the commits API newest-first
with `until=2021-01-01` and stops at 1000 per repository. Author dates in `data/raw`
(pilot copy on the Mac): linux 2020-07..2020-12, postgresql 2020-06..2020-12, mysql
2020-03..2020-12, apache 2019-04..2020-12, nginx 2016-04..2020-12. The research decision
(`docs/research/SUMMARY.md:39`) was `git clone --mirror` + `git log` over the full
history; it was never implemented.

**D2. There is no PR text at all.** Every record has `"source": "commit"`
(`collect/pipeline.py:17`). `docs/PROJECT.md` §2 asks for commit **and PR** text, and the
owner's real inputs are PR descriptions. The model has never seen a PR-shaped target.

**D3. Targets are dirty.** Measured on `data/raw/*.jsonl`: mysql 241/1000 empty
messages and 315/1000 under 40 chars; apache 1000/1000 carry a `git-svn-id:` trailer;
linux 458/500 carry `Signed-off-by:`; merges: linux 49/500, mysql 171/1000. The plan log
(`docs/plans/tonofdevelopervoice-v1.md:241`) already records 36/550 empty `output` rows in
the real training set. The model is being taught to emit nothing, to emit merge
boilerplate, and to invent trailers with people's names.

**D4. The dataset is tiny.** Real run: 550 train / 50 eval pairs sampled from 5000
records (`tonofdevelopervoice-v1.md:299`). The copy on the Mac is the older 87/13 pilot;
`data/` is not synchronised between hosts and has no manifest, so nobody can say which
dataset produced which adapter.

**D5. One synthesis style.** `scripts/synthesize.py:21-28` uses a single system prompt
("hedging, bulleted 'Changes:' list, generic verbs") with one 27B model. The fine-tune
learned to invert that one transformation. Real inputs do not look like that (the owner's
are long, already technical, markdown-free), so the model falls back to continuation =
copying. 18/550 inputs also leak a code fence (`tonofdevelopervoice-v1.md:242`); synthesis
output is not validated.

**D6. Split by sha only.** `dataset/assemble.py:29-45`. Backports and cherry-picks
(postgresql, mysql) have different shas and identical text; they can sit on both sides of
the split. The pilot already has 83 unique outputs in 87 rows.

## 3. Training (why it copies — part 2)

**T1. Loss is computed on the prompt too.** `training/train.py:34-36` concatenates prompt
and output into one `text` field and `train.py:67` trains on it as plain language
modelling. In most rows more than half of the tokens are the verbose synthetic input, so
most of the gradient teaches the model to *produce AI-style text*. The reported
`train_loss=1.36` / `eval_loss=1.435` are not completion losses and cannot be compared
with anything.

**T2. EOS is not under the project's control.** `format_example` appends no EOS token.
Whether the sequence ends with EOS depends on TRL 0.24.0 internals as patched by Unsloth.
UNVERIFIED in this audit (no GPU environment on the Mac); task
`30-training/02-completion-only-loss` verifies it on a collated batch instead of assuming.

**T3. Silent truncation at 1024 tokens.** Over-long pairs lose their ending (and their
EOS) instead of being dropped. With PR text in the corpus 1024 is too short in any case.

**T4. 105 optimizer steps, fixed 3 epochs, no seed, no warm-up, no best-checkpoint
selection.** `train.py:60-72`. The run cannot be reproduced and the last checkpoint is
taken regardless of eval loss.

**T5. Unpinned environment.** `training/requirements.txt` has bare names. The run already
hit a torch/torchvision ABI mismatch (`tonofdevelopervoice-v1.md:261-263`). Versions that
actually trained v1 are only recorded in `training/output/README.md`: PEFT 0.21.0, TRL
0.24.0, Transformers 5.5.0, PyTorch 2.11.0+cu128, Datasets 4.3.0, Tokenizers 0.22.2.

**T6. Training ends with an adapter, not a deployable model.** No merge, no quantised
export, no smoke generation. That gap is what forced the fp16 PEFT workaround on the Mac.

## 4. Evaluation (why nobody noticed)

**E1. The main metric rewards copying.** `evaluate/metrics.py:31-32`:
`content_similarity(output, source)`; a verbatim copy scores 1.0. There is no copy rate,
length ratio, truncation rate, empty rate, trailer-leak rate or fact-retention check.

**E2. Evaluation set = same distribution as training.** Same synthesis prompt, same
repositories, same month. The first out-of-distribution input (the owner's) failed 2/2.

**E3. No baseline.** Nothing compares the fine-tune with the untouched input or with a
plain instruct model given a good prompt. If a prompted instruct model wins, fine-tuning
is not justified at all.

**E4. Evaluation bypasses the shipped path.** `scripts/generate_eval_outputs.py`
hard-codes `UnslothInferenceBackend`. See S4.

**E5. The v1 "acceptance" samples were already a warning.** The plan log quotes the model
turning a paragraph into `"Authentication module improvements."` — all facts lost. It was
read as success because it was short.

## 5. Documentation drift

`docs/PROJECT.md` §2, §3 and §4 still say training runs "via Soup"; the framework decision
changed to Unsloth. The ledger has no row for PR collection or for on-device inference.

## 6. Target architecture

```
training host (RTX 5090)                          MacBook (M2)
------------------------                          ------------
git clone --filter=tree:0  ─┐
GitHub API (PR bodies)     ─┼─> clean ─> synthesize (6+ styles) ─> dataset v2 + manifest
                            │
train.py (completion-only loss, explicit EOS, 4096 ctx, best checkpoint)
   └─> export.py: merge LoRA into bf16 base ─> HF Hub ─> convert_mlx.py: MLX 4-bit (~4.6 GB)
                                                          └─> MlxInferenceBackend (in process)
                                                               ├─ CLI / web / batch_rewrite
                                                               └─ generate_eval_outputs ─> evaluate
```

One deployable artefact (MLX 4-bit). Evaluation gates run on the Mac through that exact
artefact, so what is measured is what is used.
